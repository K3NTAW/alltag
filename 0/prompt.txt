fix: Vercel functions crash with ERR_MODULE_NOT_FOUND; add .js extensions to relative imports in api/ (ESM)
- discovery: Bug, production-blocking: every serverless function on Vercel fails at load. Runtime log on the 04f000c preview:
`Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/var/task/api/_lib/cors' imported from /var/task/api/health.js`.
Cause: package.json has "type": "module", so Vercel runs the compiled api/*.js as native Node ESM, which requires explicit file extensions on relative imports. api/*.ts import "./_lib/cors" and "./_prompts/<name>" without one. Vitest resolves bare paths, so the test suite never saw it.

Fix:
1. In every non-test file under api/ (api/*.ts, api/_lib/**, api/_prompts/**), change each RUNTIME relative import/export specifier to end in ".js" (e.g. `from "./_lib/cors.js"`, `from "./_prompts/scene.js"`). TypeScript with moduleResolution "bundler" resolves ".js" to the .ts source, so tsc and vitest keep working. `import type` specifiers may stay as they are (erased at compile), but changing them is fine.
2. Do not import runtime values from ../src from api code; if any non-type import from ../src exists, report it (types-only imports are fine).
3. Add api/esm-imports.test.ts: reads every non-test .ts file under api/ (recursive), and asserts that every relative specifier in a non-type `import ... from` / `export ... from` statement (multi-line aware) ends with ".js". It must fail on the current tree and pass after the fix.
4. Test files may keep bare specifiers; leave them unless tsc complains.
