## Hard constraints
- Stack: Vite + React 19 + TypeScript strict + Tailwind v4, pnpm, vitest, eslint (flat config). Mobile-first PWA. Hosting: Vercel, serverless functions under api/ (Node runtime, `@vercel/node` types).
- Partners (min 2, we use 3): Gradium (STT + TTS WebSockets, voice design), Google Gemini (vision + dialogue + corrections, `@google/genai`), Entire CLI (records agent sessions behind commits; a human installs it, see below).
- Secrets only in env: GEMINI_API_KEY, GRADIUM_API_KEY. Never in the repo. `.env.example` lists them.
- Browser never holds the Gradium key. Gradium browser auth: the server exchanges its API key for a short-lived single-use token, the browser connects to `wss://api.gradium.ai/api/speech/asr` and `wss://api.gradium.ai/api/speech/tts` with `?token=...`. TTS first message: `{"type":"setup","voice_id":"<id>","output_format":"pcm"}`. STT: 24 kHz 16-bit mono PCM in 1920-sample (80 ms) chunks; `step` messages carry semantic VAD inactivity probabilities per horizon (0.5/1/2/3 s), turn ends when the 3 s horizon exceeds 0.5; `send_flush` forces a turn boundary; `json_config.language = "fr"`; `delay_in_frames` 10. Header auth `x-api-key` for server-side calls. Docs: https://docs.gradium.ai/ and https://docs.gradium.ai/llms.txt.
- Gemini: use `@google/genai`, model alias from env GEMINI_MODEL (default `gemini-2.5-flash`), structured JSON output via responseSchema. Vision call gets one JPEG (<=1024 px long edge) + the learner profile. Dialogue and corrections are two separate calls (in character vs grader). Never let the grader call change the roleplay.
- Gate: `.claude/hooks/tests-green.sh` runs `npm test -- --watch=false`, `npx tsc --noEmit`, `npm run lint`. Every task's acceptance names vitest files under `src/**/*.test.ts(x)` or `api/**/*.test.ts`. Tests mock `fetch` and WebSocket; no network in tests.
- One target language in the demo: French. Native: English. Tutor name Noé, barista persona. Copy is lowercase-calm, no emoji, no streaks/XP.
- Keep every task small enough to merge inside 60 minutes. The hackathon clock beats polish. Prefer fewer files, plain React state, no state library, no router library (a tiny `useScreen()` switch is enough), localStorage for persistence.

## Build order (file these as atomic execute tasks with depends_on; complexity 3 to 5 so nothing waits on spec review; one executor per task, Claude opus is the only executor)
A. Scaffold (no deps): `pnpm create vite` layout committed by hand (do not run a generator that prompts), Tailwind v4 via `@tailwindcss/vite`, vitest + @testing-library/react + jsdom, eslint flat config with typescript-eslint and react-hooks, `vercel.json` (framework vite, functions api/**), `api/health.ts` returning `{ok:true}`, `src/styles/tokens.css` with the design tokens, `src/lib/screen.ts` (`useScreen` with screens look|scene|roleplay|corrections|review|diary|settings), README.md skeleton with sections in idea.md section 11, `.env.example`, `.gitignore` for node. Acceptance: `api/health.test.ts`, `src/lib/screen.test.ts`; gate green.
B. Scene API (deps A): `api/scene.ts` POST {imageBase64, level, knownWords[]} -> `SceneResult` (`src/lib/types.ts`: place, objects[{id, fr, en, article, gender, plural, level, phrase_fr, phrase_en, bbox?}], task{fr,en,role}). Gemini vision with responseSchema; prompt in `api/_prompts/scene.ts`; 95 % known-words rule and max 6 objects stated in the prompt. Tests mock the Gemini client. Acceptance: `api/scene.test.ts` (schema validation of a fixture, error on missing image, prompt contains level and known words).
C. Turn + correct APIs (deps A, parallel with B): `api/turn.ts` POST {scene, history[], userText, level} -> {reply_fr, reply_en, task_done:boolean}; `api/correct.ts` POST {scene, userText, level} -> {corrections[{said, better, type: article|gender|case|tense|word_order|vocab|register, why_en}], kept_phrase_fr}. Prompts in `api/_prompts/`. Acceptance: `api/turn.test.ts`, `api/correct.test.ts`.
D. Gradium token + voice client (deps A, parallel with B/C): `api/gradium-token.ts` (server-side exchange, returns {token, expires_at}, never the key); `src/voice/stt.ts` (mic -> AudioWorklet resample to 24 kHz PCM16 -> WS; emits partial text, final text on VAD turn end or flush; `src/voice/pcm-worklet.ts`); `src/voice/tts.ts` (text -> WS -> streamed PCM -> AudioContext playback with `stop()` for barge-in); `src/voice/useVoice.ts` state machine idle|listening|thinking|speaking. Tests use a fake WebSocket class. Acceptance: `src/voice/stt.test.ts` (chunking at 1920 samples, turn end on step probability), `src/voice/tts.test.ts` (setup message first, stop() closes), `api/gradium-token.test.ts` (no key in the response body).
E. Look screens (deps B): camera viewfinder (`getUserMedia` rear camera, capture to canvas, JPEG <=1024 px), scanning state, scene labels over the frozen frame (pills with leader dots, known/due dots), object sheet (keep -> SRS store from task G's interface: define `src/srs/store.ts` interface now with `keep(card)`, `due()`, `grade(id, 0..5)`, implement SM-2 here minimally so E does not wait on G). Match boards CameraIdle, CameraScanning, SceneLabels, ObjectSheet. Acceptance: `src/screens/Look.test.tsx` (renders labels from a fixture SceneResult, keep adds a card), `src/srs/store.test.ts` (SM-2 intervals 1, 6, then ×ease).
F. Roleplay + corrections screens (deps C, D, E): task pill, tutor bubble, mic control 4 states, transcript stack, barge-in (speaking + hold -> tts.stop()), after `task_done` or 4 turns -> corrections screen (cards per STYLE), "Keep both and continue" -> cards into store -> ExchangeDone screen with "you can now say". Acceptance: `src/screens/Roleplay.test.tsx` (state transitions with fake voice + mocked fetch), `src/screens/Corrections.test.tsx`.
G. Review + diary + recall (deps E; parallel with F): review queue grouped by error type, review card with photo crop + hold to talk, result with next-due, diary grid, camera recall: when a new SceneResult contains an object whose card is due, the roleplay opens with it (hook in Look -> Roleplay handoff, interface documented). Settings screen (language/level/voice/speed, data note). Acceptance: `src/screens/Review.test.tsx`, `src/screens/Diary.test.tsx`, `src/srs/recall.test.ts`.
H. Docs + ship (deps F, G): README complete per idea.md section 11 (setup, env, architecture diagram as ASCII or SVG, API table with request/response schemas, partner tech with file paths, learning design, latency table placeholder the human fills from the venue, Entire section, what we did not build), `docs/ARCHITECTURE.md`, `docs/API.md`, PWA manifest + icons (SVG), `vercel.json` verified. Acceptance: `docs/readme.test.ts` (README contains every api/ route name and every env var from .env.example).
